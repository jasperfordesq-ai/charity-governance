ARCHIVED_RECOVERY_SET_V2. It requires the exact completed metadata-window evidence
and exported-snapshot evidence, validates the original window fact hash, identity,
configuration and window linkage, and matches the snapshot digest/database/OID/
observer/PID to the imported context of the exact stored source report.

All original source/report/index/dump/document checks remain. The genuine source
report still requires committed helper provenance, identity/capacity, successful
isolated restore, dump integrity, exact public.Document projection and metadata
agreement. The authenticated index still reconciles full rows, objects and every
exact encrypted document receipt. The database and each file are read back,
decrypted and hash-verified before root preparation and fresh verification.

The V2 manifest stores the complete interval under its root MAC, so a later reader
can learn and revalidate it without retaining local interval objects. It uses the
strict separate CHARITYPILOT_ARCHIVED_RECOVERY_SET_V2 MAC purpose/domain. A V2-to-V1
payload downgrade cannot reuse the tag. Existing V1 preparation/readers and
historical formats remain supported unchanged; older implementations refuse V2.

S3 metadata target constants ending in V1 continue to denote the existing immutable
file-layout/transport convention (root.json/prepared-root.json). They admit only
an explicit matching payload format/kind pair. No key/path change, automatic
upgrade or overwrite exists; conditional creation for a unique set ID remains.
Payload authentication and semantics belong to the archived-set coordinator.

`verifySet` rechecks both stored source context and signed completed interval and
returns completedIntervalBindingVerified=true for V2. This verifies bindings of
observations supplied by the trusted capture producer; it is not independent
hardware/provider attestation. The result remains QUARANTINE_ONLY with external
consistency verification required, wholeBackendQuiesced=false and
actionAuthorized=false. Current policy, disposal, production restore and reopening
are not granted by a valid archive.

## Native executed common workflow

The disposable TLS PostgreSQL workflow generates the actual full source/isolated-
restore proof and dump inside the real guarded metadata interval. It reads the
synthetic public.Document rows in a real SQL transaction, recording that actual
transaction ID and server UTC timestamp. The index does not invent a snapshot
transaction ID; metadata equality to the original imported view is verified by
the existing canonical source-report projection. This metadata read is a separate
Read Committed transaction, not a claim that the exporter acquired a global XID.

The actual AES-GCM/database and document encryption, KMS key adapters, multipart
S3 database archive, exact-version document/archive metadata, authenticated index
and V2 root classes are used. The SDK signs AWS requests, while an explicitly
synthetic in-process transport supplies storage/KMS responses. The previous
archive test backend was moved into a shared fixture with the same behaviour;
no permissive fabricated report replaces the actual native source report.

Database/report custody is established before the file visitor. The actual file
capture visitor encrypts the bytes against the full proof's dump hash and records
its exact receipt. After the outer interval completes and its holder disconnects,
the native workflow seals/stores the index and prepares/stages the V2 root. A
substituted snapshot digest refuses preparation without new writes. An unknown
final-root acknowledgement is then reconciled with a fresh reader: no new write
or data-key generation, with full decryption/hash checks and signed interval intact.

The fresh reader receives the trusted root pin/configuration. It needs no source
SQL or original files, but the storage/key fixture remains in the same process.
This is not source-VM-off, independently provisioned cloud/IAM/key-custody proof,
unknown-root discovery or a production backup supervisor. Synthetic database and
plaintext test buffers/owned keys are cleared and disposable artifacts cleaned.
