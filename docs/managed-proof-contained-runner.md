# Fixed kernel-contained source runner

17 October 2026. Source implementation with actual non-root Linux synthetic service acceptance. This is not a deployment or whole source-host-loss proof.

## Default path and custody

`runManagedImportedProof` defaults to KERNEL_CONTAINED. Unsupported/root hosts refuse before starting work; there is no automatic IPC fallback. The existing cross-platform SQL source fixture explicitly selects INTERNAL_IPC_PROOF and asserts kernelContained=false/servicePin=null. That internal proof remains useful for SQL/crypto/acknowledgement regressions; it cannot satisfy production process containment or independent recovery gates. Personal-server installers, update/recovery wrappers and support scope are unchanged.

The fixed production path verifies canonical Git origin, exact current release SHA and exact committed bytes for the eight executor modules, then checks the existing non-root systemd user manager, cgroup-v2 support and absence of the proposed job unit. It creates no persistent service, enables no user manager and accepts no executable selection from CLI or job input. Module line endings are explicitly LF to keep raw-byte source verification portable. Dependency callbacks/alternate guardian modules exist only as source-test seams and are not application settings or public endpoints.

After the original local/cloud job request acknowledgement, a fresh bounded transient service starts the fixed guardian. Its private channel verifies the live manager identity. The source callback writes/readbacks `proof-job.service.json`, awaits the original live `jobCustody.bindService` acknowledgement when applicable, checks cancellation and only then returns true to release the original input. Database credentials/environment travel through the private socket, not command arguments or launch receipts. Unsafe Node/loader/invocation overrides are removed. An unknown custody acknowledgement cannot release or retry work.

## Service lifetime and success

The service uses Type=exec, KillMode=control-group, Restart=no, NoNewPrivileges=yes, 1 GiB memory, 128 tasks, at most one CPU, a bounded runtime tied to the original worker deadline and a five-second stop budget. Actual cgroup limits are read before releasing work. The remaining daemon/container budget is a separate unresolved requirement.

Systemd documents [service lifetime and RemainAfterExit](https://raw.githubusercontent.com/systemd/systemd/main/man/systemd.service.xml) and [transient service creation](https://raw.githubusercontent.com/systemd/systemd/main/man/systemd-run.xml). RemainAfterExit preserves the exact invocation after its main process finishes so the caller can observe terminal fields before stopping/removing its own service. It is not a recovery lease or restart mechanism.

A socket reply alone cannot produce success. The launcher also requires the original invocation/start identity, no main PID, successful exit/status and an empty original cgroup. It stops only the fresh proposed unit through the manager, checks terminal state/original cgroup emptiness again and resets only that unit. No saved numeric PID or process-name lookup is used for termination. A separate running service must survive acceptance tests.

Closing the private parent connection first requests cancellation from a surviving guardian. The bounded manager stop then prevents the owned process cohort continuing. Cancellation/unknown launch/guardian loss remains unresolved even after observed cohort absence. If service ownership, stop or original cgroup emptiness cannot be proved, the protected launch request/socket directory is retained. The original helper runner refuses Docker reconciliation while cohort termination is unknown, writes only an unresolved/absence-unverified observation if possible and preserves quarantine. A saved launch request is inspection metadata, never permission to restart or kill a recovered PID.
