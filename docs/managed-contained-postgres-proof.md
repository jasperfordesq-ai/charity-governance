# Genuine PostgreSQL capture through the contained runner

17 October 2026. Executable synthetic acceptance in an isolated source checkout with its own dependency/build outputs. No production application configuration or data is used.

## Selecting the path

The existing `scripts/managed-database-writer-fence-postgres.test.mjs` keeps its cross-platform INTERNAL_IPC_PROOF default. Set `CHARITYPILOT_TEST_CONTAINED_SOURCE=1` only on non-root Linux with an existing systemd user manager, cgroup v2 and the verified local Docker Unix socket. The selector accepts only zero/one; unsupported hosts and malformed selectors refuse rather than substitute another test. The contained variant has a separate bounded eight-minute allowance; the ordinary four-minute gate is unchanged.

Both modes print their source execution mode. The contained variant omits an execution-mode override when calling the original source helper runner, exercising its KERNEL_CONTAINED default. It requires kernelContained=true and a service pin. The ordinary fixture explicitly selects IPC and requires kernelContained=false/servicePin=null.

## End-to-end observations

The cohort uses actual disposable TLS PostgreSQL, a live exported transaction snapshot, the guarded original metadata window, real dump/fingerprint/isolated restore, protected output files, crypto/archive implementations and signed SDK transports. The SQL source container, generated roles, documents, certificates and file bytes are synthetic. The fixture explicitly sets its public CA certificate to 0644 and private key to 0600 inside its owner-only directory, so a group-writable account umask cannot undermine CA transport. The strict helper guard is unchanged. Inserts committed after snapshot export must not appear in the imported view.

The contained source uses the fixed release-byte-verified launcher and original local/cloud job/service acknowledgement ordering. After original holder disconnection and removal of full local dump/report/ciphertext files, fresh clients must discover the original candidate/job/service pins without caller-memory identifiers. Read-only local inspection also checks the exact service record. Matching saved job, release and service identity is metadata evidence; no reader recreates an execution acknowledgement or repair/retry permission.

The common cohorts retain success and lost root/report/request/job acknowledgements. Contained mode adds loss of the original service acknowledgement after storage: its service record remains discoverable, the outcome is unresolved, no full dump/report/ciphertext, data key or final root may be produced, and the original request cannot be replayed. The existing source scope, role, writer, metadata-window, expiry and legacy refusal checks stay in the same executable gate.

## Running without changing the application checkout

Use a disposable exact-commit canonical checkout with its own lockfile-pinned dependencies, generated Prisma client and shared/API build output. Verify the operator, available resources, local daemon, cached pinned PostgreSQL image and existing user manager before the test. A separate temporary Git bundle may carry an unpublished descendant commit into that isolated checkout while preserving the canonical origin and exact HEAD; it does not change the running application's checkout or branch.

Keep a protected ownership/scope marker, exact source SHA, toolchain versions, bounded test handle and logs so interruption can be inspected without restarting unknown work. Build the shared package before the API. Compilation capacity and test process containment are separate resource settings. Clean only the positively owned disposable checkout/cache/artifacts after its operations are terminal and application checkout identity is rechecked. Do not use an application install/update/migration path for these test fixtures.

## Failure diagnostics

The contained runner discards worker diagnostic contents by default. An explicitly supplied original-caller observer can receive bounded helper-redacted stderr through the private live socket. Decoded copies are cleared after the callback, the total is bounded to 64 KiB and any stderr prevents a success acknowledgement. No diagnostic body is written to custody or service-manager command arguments. Synthetic kernel tests cover explicit delivery, default discard and unchanged unresolved/cleanup semantics. The SQL fixture also records phase names and artifact-presence flags to distinguish startup, custody and worker failure without printing credentials or snapshot contents.

## Limits

Cloud/KMS request handling is still an in-process synthetic backend, and the main fixture process remains alive. This gate cannot establish actual independent provider/IAM/key/current-preservation custody, source-host-off recovery, complete resource accounting or guarded application reopening. Actual launcher parent death/orphan ownership and pending daemon requests remain separate gates. Historical replay/C1, unexplained source-refusal and unattributed scratch-volume uncertainty are preserved. Full multi-organisation and optional-Confluence scope remains active.
