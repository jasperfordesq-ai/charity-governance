# Calling-process loss during genuine contained source work

17 October 2026. Synthetic fault acceptance with a real source SQL client. No application deployment, production data or provider resource is used.

## Fault boundary

On a non-root Linux test host with the current canonical checkout/build, existing user manager and verified local daemon, set `CHARITYPILOT_TEST_CONTAINED_PARENT=1` for `scripts/managed-contained-parent-loss.native.test.mjs`. The ordinary test selection does not enable it. The driver starts an owned original source process directly, without a nested test-runner process, and explicitly selects the contained source fixture.

After the original local/cloud job and service acknowledgements, a source-only barrier sends the separate driver the original pins and synthetic source metadata over its inherited private IPC. The barrier neither creates nor replaces a production acknowledgement. It is bounded, responds only to the original job's release message and refuses unsupported invocation. No database password, snapshot identifier or key payload is sent.

The driver records those original pins in its own protected directory, verifies the live manager invocation and source container, and locks a synthetic public table through a separate source connection. It releases the original callback only after the lock is acquired. Before stopping the caller it must observe an accepted exact-job proof container, a real SQL lock waiter and the running guardian/worker cgroup. A queued promise or existing descriptor alone is insufficient.

The fault uses the still-owned calling ChildProcess handle. No PID read from an old receipt is killed. The original guardian must survive the caller, stop its worker, remove that job's accepted daemon clients and leave its original cgroup empty. The exact original source and a separately labelled other job must remain running. The driver then stops only positively owned synthetic test resources. It learns the private socket directory from the live original guardian command line, checks its path, owner, mode and socket type, and removes that test-owned directory only after the original cohort is empty. This does not create a general restart-cleanup permission.

## Observed acceptance

The non-root Linux cohort passed with real TLS PostgreSQL, an original acknowledged contained invocation, a labelled source client blocked on a synthetic table, caller SIGKILL, empty original cgroup, absent exact-job clients, surviving source/control containers and a fresh read-only reader. The strengthened test including its own socket-directory cleanup passed in approximately 6.1 seconds. Exact source revisions, logs and subsequent release checks are recorded in the private checkpoint.

The first trial did not reach the intended crash. Its separate control container lacked the required creation-time label, so the helper correctly refused the metadata. The diagnostic fixture was corrected; the strict helper validation was unchanged. Both the real labelled client and SQL waiter remain required before the fault. A script-transfer syntax error in a subsequent trial also preceded execution and is retained in the private log.

## Independent local inspection

After the caller's terminal SIGKILL, a new reader process opens the original protected workspace using the pins retained by the separate driver. The service identity must match. Because the original caller never wrote its result, REQUESTED_ONLY with no observation is expected; it must not be interpreted as proof that work never started. The reader must refuse a replay write and return false execution/publication/action authority.

The original cgroup observation is retained by the surviving test driver before the fault. This is test observation custody, not a new durable production cgroup record or a supported restart/cleanup lease. Cleanup still verifies the current original invocation and uses only live test-owned resources.

## Evidence limits

The SQL, read/restore clients, process loss and kernel/daemon cleanup are real; data, roles, certificates and keys are synthetic. The source's in-process cloud/KMS transport dies with it. This test therefore cannot establish independently surviving cloud custody, trusted current policy/key authority or physical VM loss. General pending daemon requests, orphan inventory and an operator workflow after an unobserved source restart remain separate work. No old observation authorises execution, source erasure, reopening or admission.

The full multi-organisation/optional-Confluence and independent source-host recovery goal remains active. C1/replay uncertainty and the older unexplained refusal/unattributed resource are retained separately. The private dated checkpoint records exact commits, results, cleanup and failures.
